Santa Fe City Transparency Portal — Scraping Feasibility Assessment
======================================================================
URL: https://transparencia.santafeciudad.gov.ar
Date assessed: 2026-06-27


VERDICT: FEASIBLE — highly recommended
---------------------------------------


LEGAL / TECHNICAL ACCESS
-------------------------
- robots.txt: Only /wp-admin/ is blocked. All content pages are freely crawlable.
- Authentication: None required. All pages and PDFs are publicly accessible.
- REST API: WordPress REST API is available but the "normativa" custom post type
  is NOT exposed — HTML scraping is required.


DOCUMENT CORPUS
---------------
- ~14,500+ normativa documents across 15 sitemaps (2017–2026), ~1,000 URLs each.
- 6 document types:
    * Decreto DMM
    * Decreto DPB
    * Ordenanza
    * Resolución Conjunta
    * Resolución DEM
    * Resolución HCM
- Each individual page at /normativa/[slug]/ contains:
    type, year, issuing secretariat, topic, expedient number, signatories.


CRITICAL FINDING — PDFs ARE NOT CONSISTENT
-------------------------------------------
- Newer documents (2026): each page has a direct PDF link at
  /wp-content/uploads/YEAR/MONTH/filename.pdf
  The PDF filename is NOT predictable from the document number — each page must
  be scraped individually to discover the actual file URL.
- Older documents (2018 and earlier): full text is rendered as inline HTML,
  no PDF attached. The text is still extractable from the page body.


RECOMMENDED SCRAPING STRATEGY
------------------------------
1. Enumerate: parse the 15 normativa-sitemap*.xml files to collect all ~14,500
   document URLs (cleaner than paginating /normativas/ across 1,451 pages).
2. Scrape each page: extract metadata + check for a PDF link.
     - If PDF found  → download the file from wp-content/uploads/
     - If text-only  → extract the inline HTML body text
3. Rate limit: no Crawl-delay is set in robots.txt, but ~0.5 s between requests
   (matching the existing downloader config) is appropriate for a gov server.


SITEMAP STRUCTURE
-----------------
Main index: https://transparencia.santafeciudad.gov.ar/sitemap_index.xml
  normativa-sitemap.xml   (+ numbered up to normativa-sitemap15.xml)
  compra-sitemap.xml      (+ compra-sitemap2.xml, compra-sitemap3.xml)
  contratacion-sitemap.xml
  convocatorias-sitemap.xml (+ numbered up to convocatorias-sitemap4.xml)
  tipo_norma-sitemap.xml
  reparticion-sitemap.xml
  anio-sitemap.xml
  tema-sitemap.xml


BONUS COLLECTIONS (beyond normativas)
--------------------------------------
- compra       (procurement)   — 3 sitemaps
- contratacion (contracting)   — 1 sitemap
- convocatorias (public calls) — 4 sitemaps

These can add document-type diversity not well covered by the Rosario dataset.


FIT WITH EXISTING CODEBASE
---------------------------
The pattern maps onto the existing downloader.py architecture. A new link
resolution strategy (e.g. "html_scrape_normativa") would be added alongside
the existing strategies (direct_pdf, normativa, boletin_html, html_to_pdf,
scrape_page) documented in CLAUDE.md.

The sitemaps replace the checkpoint.json enumeration role used for the Rosario
CSV-driven ingestion.
